01 · PROBLEM STATEMENT

Money launderers hide in the gaps between banks

Judging criterion 1 · Value to the community and theme fit

Why the obvious fix failed

Pooling every bank's transactions in one place works technically. In the Netherlands, five large banks did exactly that through TMNL, and it was shut down in 2024 over privacy law. Singapore's COSMIC only shares after a bank already suspects someone; the US 314(b) sharing rule is barely used.

Who benefits if it works

Banks catch schemes they cannot see alone. Regulators get an audit trail proving no customer data moved. Customers keep their transactions private. The public loses less money to fraud, trafficking and sanctions evasion.

Why it is "AI Secured"

The theme is built into every layer: data never leaves a bank, identities never reach the AI writer, the model is attacked by us to prove it does not leak, and the system runs as sandboxed containers on IBM LinuxONE.

02 · SYSTEM ARCHITECTURE, START TO END

Banks learn together; only 21 numbers ever leave a bank

Judging criteria 2 · Novelty 3 · Technical design and use of LinuxONE
  1. dataIBM's public synthetic anti-money-laundering dataset (HI-Small): 5,078,345 transactions, 5,177 labelled laundering (1 in 981). Split by sending bank: the four busiest are our banks, the fifth plays the cheater.
  2. inside each bankThe bank turns each transaction into 20 clues (amount, currency change, payment type, time of day, how many people the sender pays…), computed only from its own data.
  3. inside each bankIt downloads the shared model (21 numbers), adjusts its copy on its own transactions, then clips the change and adds random noise. Nothing exact leaves.
  4. the egress doorOne audited function is the only way out. It refuses anything that looks like rows, accounts or amounts, and logs every message with rows_shared: 0.
  5. coordinator on LinuxONEIt screens every update (size limit, influence cap, odd-one-out check), averages the rest and sends the improved model back. Ten rounds take about 40 seconds.
  6. evaluationThe shared model is scored on each bank's own test transactions. We compare it with 13 other models: 3 kinds per bank and one trained on all data pooled.
  7. red teamWe attack the update ourselves: can anyone tell whether one specific transaction was in a bank's data? We tuned the noise until the answer is near chance.
  8. alerts and reportsEach bank ranks its transactions for review; a small language model on the same CPU drafts the suspicious-activity report, and code checks every claim. A person decides.

How an alert is generated and flagged

Shared model scores every transaction (0 to 1)→ Drop same-account currency swaps and single-bank chains→ Rank the review queue (top 20)→ Flag: banks involved, label, amount→ Code writes every fact of the report→ LLM writes one assessment paragraph→ Code checks each claim; false → template→ Investigator decides

In our run, 2 of the top 20 alerts are real laundering, about 56 times the 1-in-565 base rate of the review sample. On our three recorded reports, the claim check rejected two of the LLM's drafts and the template wrote them instead.

HOW THIS MAPS TO THE JUDGING

Evidence for each criterion

1 · Value and theme fit

A real, unsolved problem

  • Cross-bank laundering is invisible to any single bank.
  • Data pooling was shut down (TMNL, 2024); this keeps data in place.
  • "AI Secured" in every layer: data, identities, model, system.
2 · Novelty

End to end, written during the event

  • Federated learning + noise inside each bank + cheater screening + attacking ourselves + an AI writer with a claim check, in one pipeline.
  • Noise level chosen by our own attack, not by a guess.
  • All code written in the 24 hours; open-source libraries listed.
3 · Technical design and LinuxONE

Both IBM labs, on s390x

  • Predictive, multi-model: 14 models compared (logistic regression, random forest, gradient boosting per bank, pooled, federated).
  • Predictive + generative: Qwen2.5 on llama.cpp, built from source for big-endian s390x.
  • Sandboxed containers, one audited egress door, tunnel-only dashboard.
  • Measured: 1,880 MB for all containers, 2.1 s per round.
4 · Execution and pitch

Working, reproducible, honest

  • ≤ 3-minute video with a live run on the LinuxONE machine.
  • Re-running training reproduced the exact same model, bit for bit.
  • Every number traceable to a file; limits stated plainly.

Honest limits

  • The data and the attacks are synthetic. No real customer appears anywhere.
  • Privacy noise costs accuracy: AUC 0.992 → 0.982 and precision 0.248 → 0.065. We report the price.
  • The formal privacy bound at our setting (ε ≈ 46) is loose; the measured attack is the evidence.
  • The cheater screen is evaluated without privacy noise, because noise also hides a cheater. A subtler label-flipping cheater passes but costs only 0.034 AUC.
  • Bank 1's laundering cannot be detected from single transactions by any model; we report it separately instead of hiding it.
